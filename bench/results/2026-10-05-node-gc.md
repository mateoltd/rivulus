# Node GC measurement (M5 verdict: PASS)

Date: 2026-10-05. Pinned numbers taken on Node v24.21.0 (local).
Harness: `node/bench/gc-measure.js` (bands pre-registered in-file before
the first run). Fixture: 25 messages per iteration (~180B JSON each, fixed
content), K=40 iterations per arm plus 5 warmup, R=3 repeats, medians.
Mock REST shared by all arms; no token anywhere.

## Bands (pre-registered)

- survivors(a) <= 1.2 * survivors(b)
- allocated(a) <= 1.5 * allocated(b)
- rssDelta advisory only
- canary (c): survivors(c) > 10 * survivors(a), else harness invalid
- arm (d): documents cache cost, no gate

## Medians (bytes per message)

| arm | allocated | survivors | rssDelta |
|-----|-----------|-----------|----------|
| (a) binding, drop | 804.78 | 9.66 | 196.61 |
| (b) djs, cache off, drop | 5675.14 | 62.01 | 196.61 |
| (c) binding, retain (canary) | 814.51 | 353.34 | 196.61 |
| (d) djs, default caches | 6158.58 | 430.95 | 196.61 |

## Verdict

- survivors(a) 9.66 <= 1.2 * 62.01 = 74.41: PASS (6.4x better).
- allocated(a) 804.78 <= 1.5 * 5675.14 = 8512.71: PASS (7.1x better).
- canary survivors(c) 353.34 > 10 * 9.66 = 96.64: harness sensitive, PASS.
- arm (d) shows default-cache retention at 431 bytes per message against
  62 uncached: most of the discord.js baseline cost is consumer
  configuration, as predicted; the binding still wins the equal-config
  comparison by 7x on both metrics.
- rssDelta flat at 196.61 across arms: tripwire quiet.

Notes: allocated is a lower bound (V8 may collect mid-loop without forced
GC); alloc(a) ~= alloc(c) as expected (retention does not change the work
done). No nightly gate is claimed here; CI runs the harness for rot only.
